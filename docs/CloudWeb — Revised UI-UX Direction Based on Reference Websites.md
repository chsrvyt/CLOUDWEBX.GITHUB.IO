# CLOUDWEB — REVISED UI/UX SYSTEM

## STATUS

This document **replaces the previous CloudWeb UI/UX direction**.

The existing implementation is too focused on:

- dark cyber aesthetics
- orange technical accents
- AI-core visuals
- node networks
- persistent canvas backgrounds
- system diagrams
- excessive technical decoration
- repeated "AI / Software / Security" visual patterns

The new direction should move CloudWeb toward:

**minimal luxury + editorial technology + cinematic product design + intelligent interaction**

The website should still feel technical, but the technology should be expressed through **structure, motion, typography and interaction**, not through stereotypical cyber graphics.

---

# 01 — CREATIVE NORTH STAR

CloudWeb should feel like:

> **A premium technology company that happens to build extremely complex systems.**

The interface should make complex technology feel simple.

The visitor should not feel like they entered a cybersecurity dashboard.

They should feel like they entered a **high-end technology product experience**.

Primary qualities:

- Minimal
- Premium
- Intelligent
- Editorial
- Cinematic
- Precise
- Fast
- Tactile
- Confident
- Experimental in controlled ways

# 10 — HERO INTERACTION

When the page loads:

1. CLOUDWEB appears.
2. Small metadata resolves through a scramble effect.
3. Main headline reveals line by line.
4. One visual element moves into place.
5. CTA appears.
6. Everything settles.

Total sequence:

**~1 second**

Do not make the user watch a 3-second intro animation.

# 37 — MOTION SYSTEM

Keep:

**Framer Motion**

**GSAP**

**Lenis**

But reduce the number of animation primitives.

Use four primary motion categories:

### 01 — Reveal

Content enters naturally.

### 02 — Transform

Typography or imagery changes state.

### 03 — Explore

User-controlled interactions.

### 04 — Transition

Page/section changes.

Everything else should be built from these.

---

**responsive**

- bouncing
- elastic effects
- exaggerated scaling
- slow fades
- constant floating
- unnecessary rotation

Use motion to create continuity.

# 44 — CARDS

Cards should be rare.

If a section can be represented as:

**a row**

use a row.

If it can be represented as:

**a large image**

use a large image.

If it can be represented as:

**typography**

use typography.

Only use cards when the content genuinely benefits from containment.

Very subtle.

- rows
- navigation

# 46 — MOBILE

- large typography
- generous spacing

# 47 — ACCESSIBILITY

Maintain:

- keyboard navigation
- visible focus
- reduced motion
- semantic HTML

# 48 — PERFORMANCE

**perceived performance**

over visual complexity.

- WebGL
- large videos
- large project media
- secondary visualizations

Use static fallback imagery where appropriate.
